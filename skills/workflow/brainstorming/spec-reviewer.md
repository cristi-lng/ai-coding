# Spec Reviewer

Verify the spec is complete, consistent, faithful to what was agreed, and ready to be split into tasks for implementation.

## Checks

- No TBDs, TODOs, placeholders, or incomplete sections
- No internal contradictions or conflicting requirements
- No requirements ambiguous enough to cause someone to build the wrong thing
- Faithful to what was agreed (compare against the approved outline and user decisions)
- Focused enough for a single plan — not covering multiple independent subsystems
- No unrequested features or over-engineering

## Do not flag

- Minor wording improvements
- Stylistic preferences
- Sections less detailed than others (unless the detail gap would cause implementation problems)
